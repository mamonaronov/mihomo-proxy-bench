# Плохие конфиги

Сюда складываются yaml, которые уже прогоняли и которые не стоит собирать заново. `./up.sh` их не поднимает: в стенд попадают только `configs/*.yaml`, не файлы из подпапок.

Подписки `sub1` и `sub5` внутри живых схем (prod, urltest, fallback и остальные) — это провайдеры, не эти файлы. Убраны отдельные кандидаты, которые мерили одну слабую схему или одну слабую подписку.

Цифры — сводка, из‑за которой конфиг убрали.

## botpath

`url-test` только sub1+sub2+sub3, sub4/sub5 вне MATCH и AUTO.

- успех 18,9%, таймауты 0,0%
- p50 452 мс, p95 4347 мс
- длинный простой 875 проб
- уступает prod по скорости p50
- уступает sub3 по хвосту p95, хвосту p99 и разбросу

Узкий url-test по «бот-подпискам» без sub4 не держит Bot API: редкие удачи и очень длинный хвост.

## sub1

Изолированная подписка: `AUTO = url-test` только sub1.

- успех 2,0%, таймауты 0,2%
- p50 2250 мс, p95 6050 мс
- длинный простой 2427 проб
- хуже всех по скорости p50, хвосту p95 и разбросу
- уступает prod по скорости p50 и sub3 по хвосту p95, хвосту p99 и разбросу

Одна подписка sub1 почти не довозит Bot API и проигрывает по задержке всем живым схемам.

## sub5

Изолированная подписка: `AUTO = url-test` только sub5.

- успех 0,0%, таймауты 0,1%
- p50 и p95 нет: успешных проб не было
- длинный простой 3446 проб
- хуже всех по надёжности и длинному простою

Подписка sub5 в одиночку Bot API не несёт. В общих схемах она может оставаться запасным провайдером, но отдельным кандидатом её повторять не нужно.
